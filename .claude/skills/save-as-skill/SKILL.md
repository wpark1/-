# 방금 한 방식을 스킬로 저장하기

사용자가 "방금 한 방식을 스킬로 만들어줘"처럼 말하면, 이 대화에서 방금 끝낸 작업 방식을 다시 쓸 수 있는 스킬로 만들어 저장한다.

## 1. 방식 뽑아내기

대화를 되짚어 아래를 정리한다. 추측으로 채우지 말고 실제로 한 것만 쓴다.

- **무엇을 위한 방식인가**: 한 문장 목적
- **언제 쓰나**: 사용자가 이 스킬을 부를 만한 말 3~6개 (한국어 위주, 영어도 함께)
- **입력**: 사용자가 매번 줘야 하는 것 (파일, 주제, 대상 등)
- **단계**: 실제로 거친 순서. 쓴 도구·스킬·명령어, 사용자가 중간에 고쳐 달라고 한 점, 최종적으로 통한 방법을 반영
- **결과물 형식**: 표, 문서, 파일 위치, 말투 등
- **하지 말 것**: 이번 작업에서 실패했거나 사용자가 싫어한 방식

일회성 정보(이번 고객 이름, 특정 날짜, 비밀번호, API 키, 이메일 주소 등 개인정보)는 스킬에 넣지 않는다. 필요한 경우 `[고객명]`처럼 빈칸으로 둔다.

## 2. 이름 정하고 사용자에게 확인

- 이름은 영문 소문자와 하이픈만: 예) `weekly-report`, `blog-humanize`
- 정리한 내용을 짧게(이름, 언제 쓰는지, 단계 요약) 보여주고 "이대로 저장할까요?"라고 한 번 묻는다. 사용자가 이미 "바로 저장해"라고 했으면 묻지 않는다.
- 같은 이름의 스킬이 있으면 덮어쓰지 말고 새 이름을 제안하거나 업데이트할지 묻는다.

## 3. 저장

파일 위치: 저장소 루트의 `.claude/skills/<이름>/SKILL.md`
(이 저장소는 클라우드 세션마다 새로 받아지므로, 여기에 저장하고 커밋·푸시해야 다음 세션에도 남는다.)

형식:

```markdown
---
name: <이름>
description: <무엇을 하는지 한 문장>. Use when the user says "<트리거 문구1>", "<트리거 문구2>", ...
---

# <제목>

## 언제 쓰나
## 필요한 입력
## 단계
1. ...
## 결과물 형식
## 주의할 점
```

긴 예시나 템플릿은 `references/` 아래 별도 파일로 두고 SKILL.md에서 언제 읽을지 적는다.

## 4. 확인 후 커밋

1. 저장한 SKILL.md의 앞부분(name, description)이 YAML로 올바른지 확인한다: `head -6 .claude/skills/<이름>/SKILL.md`
2. git으로 커밋하고 현재 작업 브랜치에 푸시한다. 커밋 메시지: `Add <이름> skill`
3. 사용자에게 알려준다: 스킬 이름, 파일 위치, 어떻게 부르면 되는지(트리거 문구 또는 `/<이름>`), 새 세션부터 자동으로 인식된다는 점.

더 정교하게 다듬거나 테스트가 필요하면 `anthropic-skills:skill-creator` 스킬을 함께 사용한다.
